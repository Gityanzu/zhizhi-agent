## 1. 项目概述

智知 Agent 是一个企业知识库智能问答系统，支持 RAG 检索增强、Agent 工具调用、多 Agent 协作、多模态输入等功能。采用前后端分离架构，支持多用户体系和用户级 API Key 管理。

### 核心功能

- 智能问答（支持流式输出、思考过程、代码高亮）
- Agent 模式（13+ 工具调用，自动识别并调用）
- Plan 模式（任务拆解与分步执行）
- 多 Agent 协作（Planner-Executor-Reviewer-Coordinator）
- 知识库管理（文档上传、向量化、RAG 检索）
- 多用户体系（注册登录、个人 API Key）
- MCP 协议支持
- 多厂商大模型接入

## 4. 前端开发规范

### 4.1 Vue 3 组合式 API

**必须使用 `<script setup lang="ts">` 语法**，不使用 Options API。

```vue
<script setup lang="ts">
import { ref, computed, onMounted } from 'vue'
import { useRouter } from 'vue-router'
import { useAuthStore } from '@/stores/auth'

// 1. 导入
// 2. Props / Emits 定义
const props = defineProps<{ modelValue: boolean }>()
const emit = defineEmits<{ (e: 'update:modelValue', v: boolean): void }>()

// 3. 响应式状态
const loading = ref(false)
const formData = reactive({ username: '', password: '' })

// 4. 计算属性
const isDisabled = computed(() => loading.value || !formData.username)

// 5. 函数
async function handleSubmit() {
  // ...
}

// 6. 生命周期
onMounted(() => {
  // ...
})
</script>
```

### 4.2 状态管理（Pinia）

- 使用 Setup Store 语法（`defineStore + ref/computed`）
- 按领域拆分 store：`auth`、`chat`、`ui`、`knowledge` 等
- 复杂状态优先使用 store，简单组件内状态用 `ref`

```typescript
// stores/auth.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useAuthStore = defineStore('auth', () => {
  const user = ref<User | null>(null)
  const token = ref<string | null>(null)
  const isAuthenticated = computed(() => !!token.value && !!user.value)

  async function login(params: LoginParams) {
    // ...
  }

  function logout() {
    // ...
  }

  return { user, token, isAuthenticated, login, logout }
})
```

### 4.3 API 层规范

- 所有 API 调用统一在 `api/` 目录下管理
- 按领域拆分文件：`auth.ts`、`chat.ts`、`userApiKey.ts` 等
- 统一使用封装的 `api` 实例（带拦截器）
- 请求/响应类型必须定义

```typescript
// api/auth.ts
import { api } from './request'

export interface User {
  id: string
  username: string
  nickname: string | null
}

export interface LoginParams {
  username: string
  password: string
}

export interface LoginResponse {
  user: User
  token: string
}

export function login(data: LoginParams) {
  return api.post<LoginResponse>('/auth/login', data)
}
```

### 4.4 组件规范

#### 组件大小

- 单文件组件不超过 500 行（含 template + script + style）
- 超过 300 行考虑拆分子组件
- 逻辑复杂时提取到 `composables/`

#### Props 规范

- 必须定义类型，不使用 `any`
- 提供默认值（通过 `withDefaults`）
- 布尔值 Props 用 `is-` / `show-` 前缀

```typescript
const props = withDefaults(
  defineProps<{
    modelValue: string
    placeholder?: string
    disabled?: boolean
    options?: Option[]
  }>(),
  {
    placeholder: '请输入',
    disabled: false,
    options: () => [],
  }
)
```

#### 事件规范

- 事件名用 kebab-case
- 配合 `v-model` 时使用 `update:modelValue`
- 复杂事件传递对象而非多个参数

### 4.5 样式规范

- 使用 CSS 变量实现主题切换（`--bg-primary`、`--text-primary` 等）
- 作用域样式 `<style scoped>`
- 避免使用 `!important`（除非覆盖第三方组件样式）
- 响应式断点：
  - 移动端：`< 768px`
  - 平板：`768px - 1024px`
  - 桌面：`> 1024px`

```css
/* 推荐：使用 CSS 变量 */
.card {
  background: var(--bg-card);
  color: var(--text-primary);
  border-radius: var(--radius, 8px);
}

/* 响应式 */
@media (max-width: 768px) {
  .sidebar {
    position: fixed;
    transform: translateX(-100%);
  }
}
```

### 4.6 TypeScript 规范

- 开启 `strict` 模式
- 禁止使用 `any`，必要时用 `unknown` 替代
- 接口/类型定义放在 `types/` 目录或文件顶部
- 函数必须标注返回类型（简单函数可省略）

```typescript
// 推荐
function getUser(id: string): Promise<User> {
  return api.get(`/users/${id}`)
}

// 不推荐
function getUser(id: any): any {
  return api.get('/users/' + id)
}
```

## 5. 后端开发规范

### 5.1 分层架构

```
routes/      # 路由层：参数校验、调用 service、返回响应
services/    # 业务逻辑层：核心业务处理
middleware/  # 中间件：认证、日志、错误处理
db.ts        # 数据访问层：数据库连接与查询
```

**依赖方向**：routes → services → db

### 5.2 路由规范

- 路由文件按资源拆分：`auth.ts`、`chat.ts`、`userApiKeys.ts`
- RESTful 风格：`GET /users`、`POST /users`、`PUT /users/:id`、`DELETE /users/:id`
- 统一前缀 `/api`
- 路由处理函数保持精简，业务逻辑放 service

```typescript
// routes/auth.ts
import { Router } from 'express'
import { login, register, getCurrentUser } from '../services/auth'
import { requireAuth } from '../middleware/auth'

const router = Router()

router.post('/login', async (req, res) => {
  try {
    const result = await login(req.body)
    res.json(result)
  } catch (error) {
    res.status(400).json({ error: (error as Error).message })
  }
})

router.get('/me', requireAuth, async (req, res) => {
  const user = await getCurrentUser(req.userId!)
  res.json({ user })
})

export default router
```

### 5.3 Service 层规范

- 业务逻辑封装在 service 函数中
- 每个函数单一职责
- 错误抛出明确的 Error，由路由层统一处理
- 数据库操作使用参数化查询，防止 SQL 注入

```typescript
// services/auth.ts
export async function login(params: LoginParams): Promise<LoginResult> {
  const user = await findUserByUsername(params.username)
  if (!user) {
    throw new Error('用户名或密码错误')
  }

  const valid = await verifyPassword(params.password, user.password_hash)
  if (!valid) {
    throw new Error('用户名或密码错误')
  }

  const token = generateToken(user.id, user.username)
  return { user: sanitizeUser(user), token }
}
```

### 5.4 中间件规范

- 认证中间件：`requireAuth`（必须登录）、`optionalAuth`（可选）
- 错误处理中间件统一捕获异常
- 日志中间件记录请求信息

```typescript
// middleware/auth.ts
export function requireAuth(req: Request, res: Response, next: NextFunction) {
  const token = req.headers.authorization?.replace('Bearer ', '')
  if (!token) {
    return res.status(401).json({ error: '未登录' })
  }

  try {
    const payload = verifyToken(token)
    req.userId = payload.userId
    next()
  } catch {
    return res.status(401).json({ error: 'token 无效或已过期' })
  }
}
```

### 5.5 错误处理规范

- 统一错误响应格式：`{ error: string, code?: string }`
- HTTP 状态码语义化：
  - `200`：成功
  - `201`：创建成功
  - `400`：参数错误
  - `401`：未认证
  - `403`：无权限
  - `404`：资源不存在
  - `500`：服务器错误

### 5.6 环境变量

- 敏感信息通过 `.env` 文件管理，不提交 Git
- `.env.example` 提供模板
- 读取时提供默认值

```typescript
// .env
PORT=3001
DATABASE_URL=postgresql://user:pass@localhost:5432/db
JWT_SECRET=your-secret-key
ENCRYPTION_KEY=your-encryption-key

// 代码中读取
const PORT = process.env.PORT || 3001
const JWT_SECRET = process.env.JWT_SECRET || 'default-secret'
```

## 6. 数据库规范

### 6.1 表命名

- 表名：小写 + 下划线（snake_case），如 `user_api_keys`
- 主键：`id`（UUID 或自增）
- 时间字段：`created_at`、`updated_at`
- 外键：`{表名单数}_id`，如 `user_id`

### 6.2 字段规范

- 必须有主键 `id`
- 必须有 `created_at`、`updated_at` 时间戳
- 布尔字段用 `is_` 前缀，如 `is_default`、`is_active`
- 金额字段用 `NUMERIC`，不用 `FLOAT`
- 枚举值用 `CHECK` 约束或单独的枚举表

### 6.3 索引规范

- 主键自动索引
- 外键字段必须建索引
- 常用查询条件字段建索引
- 联合索引按区分度从高到低排列
- 避免过度索引（影响写入性能）

### 6.4 迁移与初始化

- 表结构初始化在 `db.ts` 中完成（CREATE TABLE IF NOT EXISTS）
- 新增表时同步更新初始化脚本
- 重要数据变更写迁移脚本

```sql
-- 建表示例
CREATE TABLE IF NOT EXISTS user_api_keys (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  provider VARCHAR(50) NOT NULL,
  name VARCHAR(100) NOT NULL,
  encrypted_key TEXT NOT NULL,
  key_prefix VARCHAR(20),
  base_url VARCHAR(500),
  is_default BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, provider, name)
);

CREATE INDEX IF NOT EXISTS idx_user_api_keys_user_id ON user_api_keys(user_id);
```

### 6.5 查询规范

- 使用参数化查询，禁止字符串拼接 SQL
- 查询只取需要的字段，不用 `SELECT *`
- 分页查询用 `LIMIT + OFFSET` 或游标分页
- 大表查询必须加 `WHERE` 条件

```typescript
// 推荐
const result = await query(
  'SELECT id, name, provider FROM user_api_keys WHERE user_id = $1',
  [userId]
)

// 不推荐
const result = await query(
  `SELECT * FROM user_api_keys WHERE user_id = '${userId}'`
)
```

## 10. 安全规范

### 10.1 前端安全

- **XSS 防护**：用户生成的 HTML 必须用 DOMPurify 消毒
- **敏感信息**：API Key、密码等不明文输出到控制台
- **Token 存储**：存 localStorage，请求时通过 Header 传递
- **路由守卫**：需要登录的页面加鉴权检查

### 10.2 后端安全

- **SQL 注入**：所有查询使用参数化
- **密码存储**：使用 scrypt/bcrypt 哈希，不明文存储
- **API Key 加密**：AES-256-CBC 加密存储数据库
- **JWT**：设置合理过期时间，密钥不硬编码
- **CORS**：配置允许的域名，不使用 `*`
- **速率限制**：登录等敏感接口加限流
- **输入校验**：所有用户输入必须校验类型和长度

### 10.3 依赖安全

- 定期更新依赖，修复已知漏洞
- 不使用来源不明的 npm 包
- `npm audit` 定期检查

## 11. 性能优化规范

### 11.1 前端性能

- **路由懒加载**：所有页面组件使用动态导入
- **组件懒加载**：大组件使用 `defineAsyncComponent`
- **虚拟滚动**：长列表（>100 条）使用虚拟滚动
- **防抖节流**：搜索、滚动等高频操作加防抖/节流
- **图片优化**：使用 WebP 格式，懒加载
- **打包优化**：合理配置 splitChunks，第三方库单独打包

### 11.2 后端性能

- **数据库索引**：常用查询字段建索引
- **连接池**：使用数据库连接池
- **缓存**：热点数据用 Redis 缓存（后续可加）
- **流式响应**：大模型输出使用 SSE 流式传输
- **异步处理**：耗时操作异步化，不阻塞主流程

### 11.3 数据库性能

- 避免 `SELECT *`，只查需要的字段
- 大表分页用游标，避免深分页
- 合理使用事务，避免长事务
- 定期 `ANALYZE` 更新统计信息
