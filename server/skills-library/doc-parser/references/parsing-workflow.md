# 文档解析深度参考

## 大文档分段处理策略

`parse_document` 单次返回上限 2 万字符。超长文档：

1. 先解析一次，拿到「文档概览 + 前 2 万字符」，从目录/标题推断章节边界
2. 告诉用户文档总规模，询问要处理哪部分（或按任务需要自行聚焦）
3. 需要后段内容时，改用 `read_file` 对已转存的中间 Markdown 按段读取，或用 `create_file` 先把已处理部分存档，避免重复解析

## 分层摘要模板

```
# 《文档名》概览
- 类型：合同 / 需求文档 / 手册 / 报告
- 篇幅：约 N 字，M 个章节
- 一句话总结：…

## 核心要点（≤7 条）
- 要点（含章节定位）

## 关键数据表
| 项目 | 值 | 出处 |

## 未覆盖/存疑
- 扫描件缺页、表格转文本丢失结构等
```

## 表格类文档的还原

PDF 表格解析后常退化为按行散落的文本。还原方法：
- 连续短行 + 数字密集 → 疑似表格，按列宽/分隔符合并还原
- 还原不确定时，原样引用并标注「表格结构可能有损」，不要臆测单元格归属

## CSV / JSON

- CSV：用 `read_file` 直读，前 5 行判断列结构，再按用户问题做统计（复杂统计建议转交「研究分析」或 code_interpreter）
- JSON：先输出结构树（键层级 + 类型），再按路径取值回答
