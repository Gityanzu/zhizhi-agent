# 调试手册补充技巧

## 读报错的正确姿势

1. 从堆栈**最底层往上**找到第一个属于你自己代码的帧（框架帧通常是受害者）
2. 报错信息常指向"发现地"而非"肇事地"——空指针在 A 处抛出，可能是 B 处没赋值
3. 同类错误连续出现时，问：这是数据问题（只此一条）还是逻辑问题（全错）？决定排查方向

## 日志学（比改代码更快）

- 在怀疑路径的入口/出口各打一条：入参、关键中间值、返回值、耗时
- 结构化打印（JSON.stringify 带 replacer 防循环引用），别拼接
- 生产环境不可加日志时：用错误码 + 上下文快照（用户 ID、参数哈希）反推

## 并发/时序问题的定位套路

- 症状关键词：偶发、负载高时出现、单步调试时不复现（观察者效应）
- 手段：给可疑操作打「时间戳 + 线程/协程 ID」日志，按时间轴排列找交叠
- 竞态确认：在怀疑的临界区人为加 sleep/锁重试，症状变化即实锤

## 环境差异对比（"我这里是好的"）

按可疑度排序对比两边：
1. 依赖锁文件（package-lock / poetry.lock）实际安装版本
2. 环境变量与配置加载顺序（打印生效值而不是以为的值）
3. 运行时版本（node/python/浏览器）与 OS 行尾符、路径分隔符
4. 数据差异：同一份种子数据在两边各跑一次

## 常见根因模式速查

| 症状 | 高频根因 |
|---|---|
| 昨天还好好的 | 依赖自动升级 / 配置中心变更 / 数据跨过某个阈值 |
| 只有某个用户出问题 | 该用户数据的边界形态（emoji、全角、超长、null） |
| 重启后恢复 | 内存泄漏 / 缓存不一致 / 连接池耗尽 |
| 测试环境没有生产有 | 配置差异、数据量级差异、网络策略 |
