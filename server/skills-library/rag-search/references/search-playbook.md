# 检索策略手册（RAG 检索深度参考）

## 查询改写决策树

```
用户问题
 ├─ 含口语/别名？ → 规范化为制度文件用语（"打卡"→"考勤"）
 ├─ 多实体复合？ → 拆成 N 个子查询分别检索
 ├─ 专名缩写？ → 展开全称 + 保留缩写各查一次
 └─ 结果稀疏？ → 逐步放宽：去限定词 → 换上位词 → 关键词单查
```

## 检索结果质量判断

| 信号 | 处置 |
|---|---|
| 片段含明确答案+数字/日期 | 直接引用 |
| 片段相关但残缺（截断/上下文缺失） | 换更细的关键词补查 |
| 片段主题词相同但语义无关 | 视为噪音，忽略 |
| 多片段相互矛盾 | 并列呈现 + 标注冲突，提示用户确认版本 |
| 全部无关 | 如实说"未找到"，给降级建议 |

## 常见反模式

- ❌ 只检索一次就断言"知识库没有"
- ❌ 把模型自身常识当成知识库内容输出（必须区分"知识库记载"与"通识"）
- ❌ 引用不存在的来源名
- ❌ 大段粘贴检索原文（应提炼后引用关键点）
